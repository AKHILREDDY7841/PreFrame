# Core tools status (2026-09-25)

This phase adds a project-scoped, browser-local working surface for Screenplay, Docs & Notes, Shot Lists, Storyboards, Production Schedule, Calendar, Call Sheets, and Locations. Tool data is stored in IndexedDB under the signed-in user and project. The project overview exports and restores these local records separately from the existing cloud project archive. The restore validates the project ID and records before writing them in one transaction. Local writes use record revisions to stop a stale tab from overwriting a newer tab.

The project opens to a grouped tool hub. Docs & Notes asks for a name before creating a document and opens directly to its writing area. The screenplay surface supports nine element labels, Ctrl+1 through Ctrl+9 type shortcuts, ordered elements, selection-anchored comments with orphaning after selected text is removed, and a printable full-script view. Shot Lists now shows an editable table with image, shot, description, size, type, movement, and estimated time; the last three descriptive fields offer presets and a custom entry. On narrow screens the same rows become cards. Shot and storyboard records can be grouped by stable screenplay scene-heading IDs and support compressed reference-image uploads. A storyboard frame can also link to a saved shot. Storyboards presents image-first frame cards. Schedule shows a 15-column day table in the confirmed order, with totals, completed and remaining day counts, and derived progress. Priority, shoot status and backup verification state are separate editable choices. Calendar offers timeline, month, week, and day views of the same schedule records, which also feed the Home Upcoming Schedule preview. Call Sheets and Locations start with focused empty states and open editors with production details. A call sheet can take a schedule snapshot and then be published read-only on this device; a published snapshot can still be deleted after confirmation. Free accounts are limited to 50 local shots and 50 local storyboard frames; Premium/Admin local accounts are not subject to that client cap.

The full cloud data path for these tools remains open. Edits do not currently sync across devices or with collaborators, so they should not be treated as durable production records without downloading local backups. The existing Supabase schema has canonical tables but the tool fields and revision-safe mutations still require integration and backend verification. The project cloud archive does not include local tool records. Schedule is still a day-row model; scene-level bookings, resource conflict detection, location-ID links, timezone-aware rescheduling, and stale call-sheet warnings remain open. The Import Script page still validates Preframe archives only and does not ingest Fountain/PDF/Final Draft. Call Sheets do not send email or track delivery; "publish" fixes a local read-only snapshot. The project owner can delete a cloud project through an owner-only Supabase function, after which this device's tool records are cleared; projects with uploaded cloud media are blocked until media cleanup is implemented. Payment and Premium checkout remain separate pending work.

Manual QA: sign in or use the local preview, open a project, and choose a tool from its band. In Docs & Notes, click New document, enter a title, write, refresh, and confirm the text remains. Add a Scene Heading in Screenplay, then add a shot and frame under that scene; select preset and Custom shot fields and confirm the table updates and survives refresh. Add a Schedule entry for today and check Timeline, Month, Week, and Day in Calendar. Add a Location, refresh, then delete it with the confirmation prompt. Publish a call sheet and confirm its fields become read-only. In Screenplay, select text, add a comment, insert text before its selection, then delete the selected text and check that its anchor becomes orphaned. Use Print / PDF and check the full screenplay and multilingual text. Open Project settings from the project overview to export local tool data, delete a test item, restore the backup, and confirm the item returns. For a cloud project owner, test project deletion only with a disposable project because deletion is permanent.
